Privacy Policy

How My Fitbit Dashboard uses Google Health data for its single owner.

Effective November 16, 2026

Who this app is for

My Fitbit Dashboard is a personal, self-hosted app maintained for one owner’s use. It is not a public service and does not offer public accounts or sign-up.

Public information pages

When these pages are served through GitHub Pages, GitHub may process ordinary visitor request information under the GitHub General Privacy Statement. These pages do not receive Fitbit or Google Health readings or the app’s OAuth credentials.

Google Health data it accesses

After the account owner authorizes access, the app uses only these read-only Google Health scopes:

  • Sleep
  • Health metrics and measurements
  • Activity and fitness

The companion reads sleep records to show the latest non-nap sleep duration and a seven-day average; daily heart-rate variability, respiratory rate, and resting heart rate; and running exercise records used to calculate current-week distance and a consecutive running-day streak. Values that Google Health does not return are omitted.

The app does not ask the owner to give it their Google password. Google handles account sign-in and the authorization flow.

How the data is used and shared

The app uses the authorized data only to calculate and display these summaries in the owner’s authenticated local dashboard and, if configured, on the owner’s CYD display. It does not sell the Google Health data or use it for advertising, analytics, profiling, model training, or unrelated purposes.

Google receives the OAuth authorization, token refresh, and Google Health API requests needed to provide the connection. Google’s handling of those requests is governed by Google’s own terms and privacy information. The app does not send health summaries to an advertising or analytics service.

Storage and retention

The OAuth credential, including refresh-token information, is kept in a local JSON file on the owner’s authorization computer and is copied to the owner’s self-hosted companion so it can poll Google Health. The companion updates this file when it refreshes an access token. The application does not encrypt this file; protection depends on access controls on the owner’s devices.

Health readings are reduced to the displayed summaries and kept in the running service’s memory. This integration does not write a persistent health-history file. Dashboard responses are served without HTTP caching. If configured, only health values bound to widgets are sent to the CYD over the authenticated local telemetry connection.

Local network and security

The companion is intended for a trusted private network or private VPN. Its local dashboard uses HTTP by default; a private VPN or other secure tunnel is needed to protect network traffic from observers on the route. Keep the companion private and restrict access to the credential file.

Revoke access or remove data

The owner can revoke the app’s access in Google Account settings. Removing the local Google Health token file and stopping the companion prevents further polling. Because this integration does not keep a persistent health history, there is no stored history file to delete.

Questions

Contact the maintainer through GitHub Issues. GitHub issues may be public. Do not post health information, account details, OAuth codes, tokens, or other sensitive information.

My Fitbit Dashboard is an independent personal project, not an official Google or Fitbit product.
